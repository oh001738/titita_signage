# TITITA 大廳看板 CMS

獨立於 OneCloud 的內容管理與大廳播放系統。Next.js 16 / React 19 / TypeScript，正式資料使用獨立 MongoDB，媒體使用持久化目錄。

## 本機開始

```powershell
pnpm install --frozen-lockfile
pnpm run setup
pnpm build
pnpm start
```

也可使用 npm 執行 scripts：`npm run setup`、`npm run build`、`npm start`；套件安裝以版控的 pnpm-lock.yaml 為準。

- 模擬範例（固定資料）：http://127.0.0.1:3002/demo
- 看板預覽（草稿／已發布）：http://127.0.0.1:3002/admin/preview
- 獨立後台：http://127.0.0.1:3002/admin
- 電視配對／播放：http://127.0.0.1:3002/display
- 帳號為 `admin`；第一次 `setup` 會將隨機初始密碼寫入忽略版控的 `.env.local` 註解。妥善保存後可移除該註解，登入驗證使用 scrypt 雜湊。
- `setup` 不覆蓋既有設定；本機預設為模擬課表及檔案儲存。`/demo` 永遠是明確標示的模擬展示，時鐘從台灣當日 16:20 開始。
- 開發模式：`pnpm dev`。Service Worker 離線重載僅在正式建置啟用。

## 連接 OneCloud 與 Docker

### 修改管理員密碼

在已設定 `.env.local` 的部署專案目錄執行：

```sh
sh scripts/change-admin-password.sh
docker compose up -d --force-recreate signage
```

腳本相容 NAS 的 `sh`，隱藏輸入並確認新密碼，先建立權限為 600 的設定備份，再更新密碼雜湊及 session 金鑰；服務重新啟動後，所有管理員需重新登入。使用本機 Node.js，若未安裝則使用執行中的 `titita-signage` 容器（可用 `SIGNAGE_CONTAINER` 指定其他名稱）。本機 pnpm 模式請改為停止並重新啟動服務。備份含舊憑證，確認新密碼可登入後可移除。

詳見 [部署及串接文件](docs/DEPLOYMENT.md) 與 [API 契約](docs/ONECLOUD_API.md)。OneCloud 端新增的來源程式位於相鄰專案 `titita_onecloud/app/api/internal/signage/schedule/route.ts`；須先部署該版本並設定專屬金鑰。

## 目前邊界

第一版採單一 CMS 實例、單一管理員及全螢幕共用播放清單。未實作自由拖曳排版、影片、直式專屬版型、每台設備不同清單、多人權限或整份草稿預約發布；公告與海報本身可設定生效時間。海報為公開看板素材，不應上傳私人內容。

正式 MongoDB、NAS Docker、實際 OneCloud 與電視需在部署環境完成驗收，本機驗證不代表已連接正式服務。

## 天氣設定

後台「天氣設定」可修改縣市、鄉鎮市區與中央氣象署 API 授權碼，預設為臺東縣／臺東市。輸入授權碼後按「載入鄉鎮地點」取得所選縣市清單；「測試連線」只測試、不儲存，「儲存天氣設定」會驗證授權碼和地點後獨立儲存，不變更內容草稿或發布版本。已有授權碼時留白沿用，輸入新碼即可更換，不需要另外設定 Secret。看板與後台預覽共用右下角柔光漸層天氣卡，使用飽滿立體圖示、白色大字與左右分區，適合 32 吋電視觀看；約 30 秒同步設定。公告列高度會自動量測，榮耀時刻及相簿預留相應空間。天氣資料快取 15 分鐘，顯示預報溫度與 3 小時降雨機率。支援晴、晴時多雲、陰、雨、雷雨、風、霧、雪及日夜圖示；減少動態偏好會停用動畫。未設定授權碼時不顯示，資料逾時或無法更新時顯示「天氣更新中」，不沿用過期數值。

授權碼以 AES-256-GCM 加密存於 CMS 資料庫，API 不回傳原文或密文。獨立加密金鑰保存在 `DATA_DIR/weather.key`（權限 600），不受管理員密碼重設影響；請連同 CMS 資料庫一起備份，遺失此檔需重新輸入授權碼。Docker 的 signage-data volume 會保留此檔。授權碼只由伺服器以 Authorization header 傳送到氣象署。

## 活動相簿

在後台「活動相簿」新增相簿，可填活動名稱、日期、排程及播放設定，選取多張 PNG/JPEG/WebP 批次上傳（每張最多 8 MB、每本最多 100 張）。系統會保存原圖，並在管理員瀏覽器嘗試建立最長邊不超過 1920 像素的 JPEG 播放版本；若處理失敗則使用原圖。上傳的檔案儲存在 DATA_DIR/uploads，請連同 CMS 資料庫一起備份。

照片和相簿刪除後，先儲存草稿才進入回收站；已發布內容仍維持，必須發布後才影響看板。回收站保留 30 天，可提前永久刪除；到期清理由已配對且有已發布內容的播放螢幕請求觸發，若沒有螢幕連線，會延至下次播放請求處理。仍被草稿、已發布版本、上一個可還原版本或回收站引用的檔案會保留，待引用解除後再處理。播放器的離線快取及外部備份不會因伺服器刪除而自動抹除，需依設備及備份政策另外管理。

圖片寫入及清理依賴單一 CMS 實例的序列化寫入；不要同時啟動多個 CMS 實例共用同一資料庫和媒體目錄。

## 榮耀時刻播放

後台「看板預覽」會先儲存目前草稿再開啟預覽頁，可切換「草稿」與「已發布」來源；已發布模式直接讀取發布快照，不需配對設備。尚未發布時會顯示提示，不使用草稿替代正式內容。預覽與正式看板共用播放元件，預覽工具列位於播放區外；正式電視仍使用 `/display`，只讀取已發布內容。首頁進入管理後台，固定資料的 `/demo` 僅作為獨立模擬範例。

後台「榮耀時刻」可選擇「聚光登場」（每次一位學生）、「榮耀揭幕」（每頁最多三位依序進場）或經典版面。未設定效果的既有同場多獎紀錄會採榮耀揭幕，其他既有版型維持經典效果。每位／每頁停留時間可設定 5–60 秒，動畫進場後保持靜止閱讀；比賽名稱、品牌及底部公告在換頁時保持固定。

- **整場連續播完**：同一場比賽所有學生依序播放後才返回課表，不另設整場總時長上限。
- **分段播放，下次接續**：依每段目標秒數（15–180 秒，預設 45 秒）選取完整頁面，返回課表後，下次輪到該場比賽時接續下一頁。若一頁的播放時間超過目標，仍會完整播完一頁。接續進度保存在當次播放頁面，重新整理後從頭開始。

每次插播之間播放課表 40 秒，獲獎紀錄與活動相簿依排列順序穿插。`/display` 為全自動播放，沒有播放按鈕、海報按鈕或管理後台入口，滑鼠停在海報上也不會暫停；管理員完整預覽仍提供暫停與全螢幕操作。系統的減少動態偏好只關閉動畫，不停止名單輪播。新增與修改設定需先儲存草稿，再發布到螢幕。
