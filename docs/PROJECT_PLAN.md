# 專案規劃

建立日期：2026-11-04（Asia/Taipei）

進度：第一版本機實作與驗證完成，詳見 VERIFICATION.md；以下環境驗收 checkbox 保留未實際驗收狀態。

## 架構

櫃台 → 獨立 CMS 後台 → CMS 內容資料與持久化媒體
教務系統 → 專用唯讀課表 API → CMS → 大廳播放頁

本專案與教務系統各自部署；第一版 CMS 後台及播放頁共用一個新容器。
教務系統僅在日後整合時新增必要的唯讀介接，需另行實作與驗證。

## 視覺方向

橫式看板：奶油白底、墨綠文字、暖橘與淡黃點綴。
左側固定今日課表；右側活動海報輪播及 LINE 入口；底部固定公告。
程式使用真實文字呈現課程與公告，插畫使用圖片素材。
概念圖不是已完成網頁，實作需驗證實際螢幕解析度與觀看距離。

## 開發順序

1. 使用模擬資料製作播放頁，處理長課名、多筆課程、空課表及跨日情境。
2. 建立獨立登入、公告及海報管理，加入預覽、排程與發布。
3. 建立螢幕配對與唯讀資料存取。
4. 訂定並串接教務課表 API，驗證取消、改期與換教室。
5. 完成 Docker、媒體持久化、自動更新及斷線備援。

## 驗收條件

- [ ] 展示頁在預定電視尺寸下文字清楚，無裁切或溢出。
- [ ] 學生 ID、聯絡方式、出勤名單、學費與請假原因等獨立欄位不進入看板資料；課程名稱依業主要求原樣保留，包含課名中的學生姓名。
- [ ] 管理員可預覽及發布公告、海報，排程按 Asia/Taipei 生效。
- [ ] 真正的 QR Code 可掃描且導向設定網址。
- [ ] 配對螢幕只能讀取已發布內容，無管理或教務資料庫權限。
- [ ] 發布後可確認螢幕取得的內容版本及最後連線時間。
- [ ] 斷線時保留可播放內容，過期課表不冒充最新資訊。
- [ ] 跨日、無課、課程過多及長文字皆有可讀版面。
- [ ] 容器重建後海報及 CMS 資料仍保留。
